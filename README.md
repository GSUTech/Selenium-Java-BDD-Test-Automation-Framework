
# Selenium Cucumber BDD Automation Framework

A personal UI test automation project built with Java, Selenium WebDriver, 
Cucumber BDD, and Maven, with Jenkins CI/CD integration.

# Project Overview

This framework demonstrates automated testing of web application functionality using the Page Object Model (POM) design pattern and behavior-driven development (BDD).

The current test application is the public demo login page at https://the-internet.herokuapp.com/login.

## Running Tests

Run the complete test suite:

```bash
mvn clean test -Dtest.runner=TestRunner
```

Run regression tests:

```bash
mvn clean test -Dtest.runner=TestRunner -Dcucumber.filter.tags=@regression
```

Run smoke tests:

```bash
mvn clean test -Dtest.runner=TestRunner -Dcucumber.filter.tags=@smoke
```

Retry previously failed scenarios:

```bash
mvn test -Dtest.runner=RetryRunner
```

The retry command requires a nonempty `target/rerun.txt` generated by a previous failed run. Do not use `clean` before retrying.

## Environment Configuration

Copy `config.properties.example` to `config.properties` and configure the required values.

The local configuration file is excluded from Git.

## Reports

Generated artifacts are stored under `target/`.

- `cucumber-report.html` — HTML report
- `cucumber-results.xml` — JUnit report
- `rerun.txt` — Failed scenario locations
- `cucumber-retry-report.html` — Retry report
- `screenshots/` — Failure screenshots

## Jenkins Integration

The Jenkins job supports parameterized execution using:

- `ENV`: qa, staging, prod
- `TEST_SUITE`: smoke, regression, all

Jenkins checks out the GitHub repository, runs the selected suite, and publishes test results.

Failed scenarios can be retried once using the retry runner.

The original test failure status is preserved.

## Framework Architecture

Feature File → Step Definitions → Page Objects → Selenium WebDriver → Browser

Hooks manage scenario setup, teardown, and failure evidence.

TestRunner controls normal Cucumber execution.

RetryRunner executes scenarios listed in the rerun file.
